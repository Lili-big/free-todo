# 数据管理与迁移

## v1.5.0 日期字段与升级

v1.5.0 增加计划开始时间，数据库升级至 schema 3。已有任务的开始时间默认为空，原计划完成日期及改期历史保留；新版本可恢复 schema 1/2 的旧备份。

升级后的数据库和 schema 3 备份需要 v1.5.0 或支持该 schema 的更高版本。若要回退旧应用，请使用升级前导出的备份，不要用旧应用直接打开升级后的数据库。

## 本地数据位置

默认数据根目录为：

```text
%LOCALAPPDATA%\personal-todo\
```

其中的主要内容为：

```text
personal-todo\
├─ data\app.sqlite3       # 正式 SQLite 数据库
├─ data\.restore\        # 恢复/升级中断恢复日志
├─ backups\safety\      # 覆盖恢复前自动生成的安全备份
├─ logs\                 # 应用运行日志，不记录任务标题和备注正文
└─ session\              # Electron 会话数据
```

不要在应用运行时直接复制 `app.sqlite3`，也不要把复制整个 `%LOCALAPPDATA%` 当作支持的迁移方式。SQLite 可能处于 WAL 模式，直接复制主文件不能保证包含已提交数据。请始终使用应用内的“数据管理 → 导出完整备份”。

## 在两台电脑之间迁移

### 电脑 A：导出

1. 打开左侧导航的“数据管理”。
2. 选择“导出完整备份”。
3. 选择本地磁盘、U 盘或可信的同步目录，并使用一个尚不存在的文件名保存。V1 不会覆盖同名旧备份。
4. 等待导出和导出后校验完成，得到一个 `.todo-backup` 文件。
5. 将该文件复制到电脑 B。使用移动介质时，请在拔出前安全弹出。

### 电脑 B：检查并恢复

1. 在电脑 B 安装与备份同版或支持该备份 schema 的更高版本。较旧应用遇到更高版本备份时会拒绝恢复。
2. 启动应用，打开“数据管理”，选择“检查并恢复备份”。
3. 选择从电脑 A 带来的 `.todo-backup` 文件。应用会先检查文件格式、数据哈希、应用与 schema 版本、SQLite 完整性、关联关系和对象数量。
4. 核对备份时间、版本和对象数量。
5. 如果确认要继续，输入界面要求的“覆盖恢复”并确认。
6. 恢复成功后，检查今日、待分配、项目、目标、日历、四象限和重复系列数据。建议再次启动应用后抽查关键内容。

企业微信日历连接信息和只读缓存不会写入 `.todo-backup`。换电脑恢复任务数据后，需要在“数据管理”中重新连接企业微信日历。

`.todo-backup` 是支持的跨电脑迁移载体，不包含源电脑用户名、系统绝对路径或 CPU 相关二进制。用户自己在任务标题或备注中输入的文本会按原文保留。

## 覆盖恢复与安全备份

恢复是**全量覆盖**，不是合并：电脑 B 当前的目标、项目、任务、历史、重复系列和设置都会被备份中的完整数据集替换。备份时点之后在电脑 B 新建或修改的内容不会与备份合并。

每次正式恢复前，应用必须先在 `backups\safety\` 创建并完整校验当前数据的安全备份。如果安全备份、磁盘空间检查或候选数据库校验失败，覆盖不会开始。V1 不会自动删除这些安全备份。

恢复过程使用候选库、不可变操作计划和持久化阶段标记。如果进程被强制结束，下次启动会在打开普通数据服务前先执行恢复判定，使数据回到完整的恢复前状态，或保留已完整提交的恢复后状态，不应出现两份数据混合。

## 隐私与明文安全边界

- V1 的 SQLite 数据库和 `.todo-backup` 备份默认为**明文数据**，不是端到端加密容器。
- 本地隐私边界主要依赖 Windows 用户账户权限。如果电脑、Windows 账户或备份介质被他人访问，其中的任务文本可能被读取。
- 如果数据敏感，建议使用 Windows 设备加密、加密 U 盘或可信的加密同步目录，并避免通过公共聊天或公开链接传输备份。
- 应用核心功能不依赖登录、云同步或遥测；备份文件由用户自行保管和传输。
- 同一磁盘上的安全备份能用于恢复失败回滚，但不能替代外部备份，也不能抵御磁盘硬件损坏。
